## Deferred items (Phase 00.5 first acceptance criteria)

Two HIGH-severity findings from the PR #32 audit were explicitly deferred to Phase 00.5:

- **H-DEFER-1 (Security):** slug-based cross-tenant linkage in `provision_initial_workspace` — `alice@x.com` + `alice@y.com` would silently share workspace via idempotency-on-slug. Founder grilled this at Round-2 Q6 and accepted as Wave-1 risk; Phase 00.5 may choose to land a fix (uuid-suffix-on-collision OR raise WorkspaceSlugConflict OR per-user provisioning UUID).
- **H-DEFER-2 (Architecture):** `register()` writes to `multitenancy.{workspaces, cells, cell_members}` with `FORCE ROW LEVEL SECURITY` — passes in CI only because testcontainers connects as the `oriion` DB-owner role (bypasses FORCE); production `oriion_app` (NOLOGIN per architect-PR) does NOT bypass. The dead `set_tenant_context` middleware (Architecture H2 from the pre-Phase-05 audit) is the same root cause. Phase 00.5 must atomically land: (a) GUC middleware setting `app.current_user_id/workspace_id/cell_id` from JWT claims, (b) a bootstrap path for `register()` (SECURITY DEFINER provisioning function OR loosened INSERT policy OR set GUCs to the just-created user_id before writes), (c) E2E fixture update `SET LOCAL ROLE oriion_app` so the production failure mode is surfaced by CI, (d) ADR-014 honesty-pass amendment.
