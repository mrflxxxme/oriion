# Phase 00.4 — LLM Gateway (DeepSeek + YandexGPT + GigaChat + BYOK + MCP infra)

- **Owner:** Tech Lead · **Duration:** 5 дней · **Status:** Pending

## Goal

LLM-gateway модуль с тремя провайдерами (DeepSeek + YandexGPT + GigaChat), BYOK-режимом, role-based routing, billing-tracking, health-check + failover. MCP-client infrastructure (без production MCP-серверов).

## Dependencies

- 00.1 (repo) + 00.3 (db)

## Tasks

1. **Gateway module** (`backend/src/llm_gateway/`)
   - [ ] Абстракции: `LLMProvider` (Protocol), `LLMRequest`, `LLMResponse`, `LLMStream`
   - [ ] `LLMRouter`: per-role policy выбор провайдера + per-cell stack_preference
   - [ ] `LLMBilling`: middleware, записывает токены и стоимость в `billing.credit_transactions`
   - [ ] `LLMHealth`: health-check каждые 30 сек per provider

2. **DeepSeek provider** (`providers/deepseek.py`)
   - [ ] SDK: `openai-python` с `base_url="https://api.deepseek.com"`
   - [ ] Модели: deepseek-chat (V3), deepseek-reasoner (R1)
   - [ ] Streaming через async generator
   - [ ] Tool-use (function calling)
   - [ ] Prompt caching (native DeepSeek)
   - [ ] Retry с exponential backoff на timeouts

3. **YandexGPT provider** (`providers/yandex.py`)
   - [ ] SDK: `yandex-cloud-ml-sdk`
   - [ ] Модели: yandexgpt-pro, yandexgpt-lite
   - [ ] Embeddings: text-search-doc, text-search-query
   - [ ] Streaming через async generator
   - [ ] Retry с exponential backoff

4. **GigaChat provider** (`providers/gigachat.py`)
   - [ ] SDK: `gigachat-py`
   - [ ] Модели: GigaChat-Pro, GigaChat-Max
   - [ ] OAuth2 auth flow

5. **Routing logic** (`router.py`)
   - [ ] ROLE_TO_MODEL mapping (см. ADR-018)
   - [ ] Cell.stack_preference handling: 'default' / 'ru-only' / 'byok-only'
   - [ ] Failover chain: DeepSeek → YandexGPT → GigaChat при недоступности
   - [ ] User opt-in failover policy per cell

6. **BYOK module** (`byok.py`)
   - [ ] `byok_keys` table: cell_id, provider, encrypted_api_key, base_url_override
   - [ ] Encryption: envelope (Yandex KMS)
   - [ ] UI flow: пользователь добавляет ключ → validation call → save в Lockbox
   - [ ] API: `POST /api/cells/<id>/byok-keys`, `GET`, `DELETE`
   - [ ] Маски в UI (показываем только последние 4 символа)

7. **Configuration**
   - [ ] `LLM_PROVIDERS` config в БД-таблице `system_config`
   - [ ] In-memory cache с invalidation через Postgres NOTIFY/LISTEN
   - [ ] Admin endpoint `POST /api/admin/llm/reload-config`

8. **API endpoints**
   - [ ] `POST /api/llm/generate` (internal use + тесты): {prompt, model_tier, max_tokens, stream} → ответ или SSE
   - [ ] `GET /api/llm/providers/status` → health всех провайдеров
   - [ ] `GET /api/cells/<id>/llm/usage` → текущее потребление T-credits

9. **Pricing engine** (`pricing.py`)
   - [ ] Прайс-таблица per модель (см. ADR-018) с meta `last_updated`
   - [ ] Function `calculate_credit_charge(provider, model, tokens_in, tokens_out, stack: ru|china|western) -> Decimal`
   - [ ] Wave 0: единый курс 1× (DeepSeek + RU). Двухставочный 3× при добавлении Western — Wave 2+

10. **Метрики и логирование**
    - [ ] OpenTelemetry spans для каждого LLM-вызова
    - [ ] Метрики: `llm_request_total`, `llm_tokens_input`, `llm_tokens_output`, `llm_cost_rub`, `llm_latency_ms`, `llm_provider_availability`
    - [ ] Структурированный лог: trace_id, cell_id, role_id, provider, model, tokens, cost

11. **MCP-client infrastructure** (`backend/src/mcp/`)
   - [ ] MCP-client framework через Pydantic-AI native support
   - [ ] `MCPConnection` model: cell_id, name, transport_type, endpoint, credentials_ref, status
   - [ ] Health-check per MCP-connection (ping каждые 60 сек)
   - [ ] Tool registration: при подключении MCP — фетчим список tools
   - [ ] **No production MCP-серверы в Wave 0** (только built-in web_search)

12. **Built-in tools (без MCP)**
    - [ ] `web_search`: Brave Search API (см. TBD_BRAVE_SEARCH_API_KEY) или Yandex Search API
    - [ ] `read_url`: httpx GET + readability-lxml content extraction
    - [ ] Rate-limit per agent (10 req/мин)

13. **Тесты**
    - [ ] Unit: mock каждого провайдера
    - [ ] Integration: реальный DeepSeek + YandexGPT + GigaChat вызовы в CI
    - [ ] Биллинг: вызов записывает корректную transaction
    - [ ] BYOK: клиентский key используется вместо managed
    - [ ] Failover: kill primary → fallback на secondary

## Acceptance Criteria

- [ ] `POST /api/llm/generate {prompt, model_tier:"deepseek-v3"}` → текстовый ответ
- [ ] `POST /api/llm/generate {prompt, model_tier:"deepseek-r1"}` → reasoning-ответ
- [ ] `POST /api/llm/generate {prompt, model_tier:"yandexgpt-pro"}` → ответ через RU-стек
- [ ] Стриминг работает (SSE)
- [ ] После вызова — запись в `credit_transactions` с tokens, cost, credit_charge
- [ ] `GET /api/llm/providers/status` → all 3 providers healthy
- [ ] BYOK flow: добавил key → вызов идёт через клиентский endpoint
- [ ] Failover: kill DeepSeek (mock) → автоматический fallback на YandexGPT
- [ ] MCP-client framework готов (можно registers MCP-connection в Wave 1)

## Risks

- **R-01** (отказ провайдера): multi-provider fallback + health-check обязательны
- **R-04** (runaway costs): per-task cost cap (50 T-credits default) — hard limit
- **R-16** (BYOK ARPU): tracking BYOK adoption rate
