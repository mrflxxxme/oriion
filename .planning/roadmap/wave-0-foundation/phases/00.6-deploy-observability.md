# Phase 00.6 — Deploy + Observability baseline

- **Owner:** DevOps · **Duration:** 3 дня · **Status:** Pending

## Goal

Воспроизводимый staging-deployment в Yandex Cloud через Docker Compose на 1 VM + Caddy + базовая observability (метрики/логи/traces в Grafana). Internal demo проходит на staging.

## Dependencies

- 00.1–00.5 — Done

## Tasks

1. **Yandex Cloud setup** (Terraform)
   - [ ] VM (4 vCPU / 8 GB / 50 GB SSD) в ru-central-1
   - [ ] Managed PostgreSQL (4 vCPU / 16 GB / 100 GB)
   - [ ] Managed Redis
   - [ ] Object Storage bucket (см. TBD_YC_OBJECT_STORAGE_BUCKET_STAGING)
   - [ ] Yandex Lockbox для secrets
   - [ ] Security groups + network ACLs
   - [ ] Domain + DNS (см. TBD_BRAND_DOMAIN_STAGING)
   - [ ] Let's Encrypt через Caddy auto-TLS

2. **Docker Compose staging-stack** (`infra/docker-compose.staging.yml`)
   - [ ] Backend (gunicorn + uvicorn workers, 4 workers)
   - [ ] Frontend (Vite build → served через Caddy)
   - [ ] Redis (если не используем managed)
   - [ ] Caddy с auto-TLS
   - [ ] OpenTelemetry collector (sidecar)
   - [ ] Prometheus + Grafana + Loki + Tempo (single-node)
   - [ ] Postgres НЕ в compose — используем managed

3. **CI/CD deploy** (GitHub Actions)
   - [ ] На merge в `main` → build images → push в Yandex Container Registry → SSH-deploy на staging VM → docker compose pull && up -d
   - [ ] Smoke-тесты после deploy: `/healthz`, `/api/auth/me` (с тест-токеном), `/api/llm/providers/status`
   - [ ] Rollback скрипт (предыдущий image tag)

4. **Observability**
   - [ ] OpenTelemetry SDK в backend (auto-instrumentation FastAPI, asyncpg, httpx)
   - [ ] Structured logs через `structlog` → JSON → Loki
   - [ ] Метрики: Prometheus client + наши custom (llm_*, task_*, billing_*)
   - [ ] Grafana dashboards: «System health», «LLM usage», «Tasks pipeline»
   - [ ] Алерты: `/healthz` fails, p95 latency, error rate, queue depth

5. **Backup**
   - [ ] Managed Postgres — auto-backup daily, retention 30 дней
   - [ ] Object Storage — versioning включён
   - [ ] Скрипт восстановления (runbook в `docs/runbooks/restore-db.md`)

6. **Secrets**
   - [ ] Yandex Lockbox содержит: Postgres password, LLM API keys (TBD_DEEPSEEK_API_KEY, TBD_YANDEX_GPT_API_KEY, TBD_GIGACHAT_AUTH_KEY), S3 keys, SMTP password (TBD_SMTP_PASSWORD)
   - [ ] Backend читает через Lockbox SDK при старте
   - [ ] Никаких секретов в `.env` на сервере

7. **Runbook'и** (`docs/runbooks/`)
   - [ ] `deploy.md`: ручной deploy/rollback
   - [ ] `incident-llm-provider-down.md`: что делать при недоступности DeepSeek/YandexGPT/GigaChat
   - [ ] `incident-db-down.md`: failover на read-replica (когда появится в Wave 4)
   - [ ] `secret-rotation.md`: ротация API-ключей

## Acceptance Criteria

- [ ] `https://staging.<TBD_BRAND_DOMAIN>` доступен с валидным TLS
- [ ] Регистрация → логин → создание cell с WB-Селлер team → постановка задачи → ответ работают в staging
- [ ] Grafana показывает: requests/s, p95 latency, LLM cost in real-time
- [ ] Алерт срабатывает при `/healthz 500` (тест-сценарий)
- [ ] Deploy через GitHub Actions: время от commit до production = <10 мин
- [ ] Rollback команда выполняется за <2 мин
- [ ] Internal demo проходит на staging — все team members могут зайти и поставить задачу

## Risks

- **R-07** (нагрузка): на staging один VM — не для нагрузочного тестирования. Load tests — отдельная инфра в Wave 3.
- **R-08**: ПДн только в Yandex Cloud РФ-зоне — Terraform module enforce'ит zone=ru-central1-*

## Notes for AI-agents

- Не использовать k8s. Docker Compose + 1 VM достаточно для Wave 0-3
- НЕ деплоить prod из dev-машины — только через CI
- НЕ хранить TLS-keys в репо — Caddy получает их автоматически
- Real-time metrics в Grafana — обязательны для production troubleshooting
