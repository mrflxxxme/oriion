# Phase 00.5 — Pydantic-AI runtime + WB-Селлер team-preset

- **Owner:** Senior Backend · **Duration:** 5 дней · **Status:** Pending

## Goal

Минимальный агентный runtime. Первый team-preset (WB-Селлер) с 3 агентами: Coordinator + Listing Writer + Researcher. Пользователь ставит задачу Coordinator'у → он декомпозирует и делегирует → ответ + цитированные источники + draft-листинг.

## Dependencies

- 00.3 (db + cell schemas), 00.4 (llm-gateway)

## Tasks

1. **Pydantic-AI integration** (`backend/src/agents/`)
   - [ ] Установить `pydantic-ai`
   - [ ] Wrapper `LLMGatewayModel` для Pydantic-AI, вызывает наш LLM-gateway вместо прямого SDK
   - [ ] MCP-client connection через Pydantic-AI native MCP support (готов из 00.4)

2. **Domain models**
   - [ ] `Role` (role_key, version, default_system_prompt, default_tools[], recommended_model_tier, risk_level, agent_archetype_id)
   - [ ] `TeamPreset` (preset_key, name, description, icon_emoji, vertical_tag, agent_bundle[], workflow_dag, recommended_plan)
   - [ ] `AgentInstance` (id, cell_id, role_key, custom_name, ui_sprite, custom_prompt?)
   - [ ] `Task` (id, cell_id, agent_id, user_id, prompt, status, result, parent_task_id?, created_at)
   - [ ] `TaskStep` (id, task_id, step_type [llm_call|tool_call|delegation], payload, started_at, finished_at, tokens, cost)

3. **Roles seed-data** (внутренняя метадата, не user-facing)
   - [ ] `coordinator`: deepseek-r1, agent_archetype_id='formal01', risk_level='medium'
   - [ ] `listing_writer`: deepseek-v3, agent_archetype_id='creative01', risk_level='low'
   - [ ] `researcher`: deepseek-v3, agent_archetype_id='hoodie01', risk_level='low'
   - [ ] System prompts vertical-aware (для WB-домена)

4. **TeamPreset seed: WB-Селлер v1** (`agents.team_presets`)
   - [ ] preset_key='wb_seller_v1'
   - [ ] icon_emoji='🛒'
   - [ ] vertical_tag='wb_seller'
   - [ ] agent_bundle = [{role: coordinator, name: «Алексей»}, {role: listing_writer, name: «Марк»}, {role: researcher, name: «Скаут»}]
   - [ ] workflow_dag: Researcher → Listing Writer → done (Coordinator orchestrates)
   - [ ] recommended_plan='solo'

5. **Cell provisioning + initial team**
   - [ ] `POST /api/cells/<id>/teams` создаёт team в cell на основе preset
   - [ ] Agent instances созданы с правильным sprite-ID + name
   - [ ] Team готов получать задачи

6. **Coordinator implementation** (`agents/coordinator.py`)
   - [ ] Vertical-aware system prompt (для WB-Селлер team)
   - [ ] Decomposition logic: получает user message → создаёт plan → делегирует
   - [ ] Tool: `delegate_task(target_agent_id, sub_prompt, context_artifacts[])`
   - [ ] Max delegation depth = 5 (защита от циклов)

7. **Tool: delegate_task** (`agents/tools/delegate.py`)
   - [ ] Pydantic input/output schemas
   - [ ] Runtime запускает sub-task в той же cell, ждёт результат
   - [ ] Sub-task создаёт TaskStep типа `delegation` с parent_task_id
   - [ ] Cost rollup: total task cost = sum sub-tasks

8. **Task execution flow** (`runtime/orchestrator.py`)
   - [ ] Coordinator-as-entry: пользователь ставит задачу Coordinator → он управляет
   - [ ] Sub-task pipeline: parent + children, общий cost rollup
   - [ ] Streaming: SSE отправляет обновления каждого sub-task
   - [ ] Cancel: пользователь может отменить task → cascade на children
   - [ ] Audit log: task_started, tool_called, delegation, task_completed

9. **API endpoints**
   - [ ] `POST /api/cells/<id>/tasks` → создаёт Task с Coordinator
   - [ ] `GET /api/cells/<id>/tasks/<tid>` → status + result
   - [ ] `GET /api/cells/<id>/tasks/<tid>/stream` → SSE real-time прогресс
   - [ ] `POST /api/cells/<id>/tasks/<tid>/cancel` → cancel

10. **Billing hook**
    - [ ] Перед стартом: проверка credits ≥ reserved (50 T-credits default)
    - [ ] После завершения: списание фактической стоимости, возврат разницы
    - [ ] При fail (LLM 503): полный возврат

11. **Vertical-aware Coordinator prompt** (WB-Селлер version) — см. ADR-022:
    - Знает WB-терминологию (FBO, FBS, артикул, остатки, выкуп, рейтинг)
    - Понимает workflow селлера
    - В team — Listing Writer (Марк), Researcher (Скаут)
    - При сложных задачах — показывает план перед exec

12. **Тесты**
    - [ ] Integration: Coordinator получает задачу «Найди топ-3 конкурента на WB по нише X и сделай draft-листинг» → делегирует Researcher → Listing Writer → возвращает структурированный ответ + draft
    - [ ] Защита от цикла: Coordinator пытается self-delegate → ошибка
    - [ ] Cost rollup: total = sum components
    - [ ] Cancel: cascade на children работает
    - [ ] Coverage ≥75%

## Acceptance Criteria

- [ ] User регистрируется → cell со spawn'ом WB-Селлер team создаётся
- [ ] `POST /api/cells/<id>/tasks {prompt:"..."}` → 202 + task_id, Coordinator выполняет
- [ ] `GET /api/cells/<id>/tasks/<id>` → status pending → running → completed
- [ ] Result содержит структурированный ответ + цитированные источники + (optional) draft-листинг
- [ ] SSE стримит прогресс sub-task'ов
- [ ] Cost рассчитан корректно (sum components)
- [ ] Internal demo: команда видит работу в реальном времени через SSE
- [ ] Latency p95 для среднего workflow (~5 steps) ≤90 сек

## Risks

- **R-02** (vertical-template качество): WB-Селлер prompts production-quality (используем in-house WB-expertise)
- **R-04** (multi-agent cost): max-depth + per-task cost cap защищают
