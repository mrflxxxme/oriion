# Phase 00.3 — PostgreSQL + RLS + Cell-aware multitenancy

- **Owner:** Senior Backend · **Duration:** 5 дней · **Status:** Pending

## Goal

PostgreSQL 16 + pgvector + RLS-политики per cell + bounded-context schemas + Alembic-миграции. Любой backend-запрос автоматически фильтруется по `cell_id` пользователя.

## Dependencies

- 00.1 (repo) — Done

## Tasks

1. **Postgres setup**
   - [ ] Postgres 16 image в Docker Compose dev
   - [ ] `pgvector` extension включён
   - [ ] `pg_stat_statements` для observability
   - [ ] Initial superuser + app-user (limited privileges)
   - [ ] Yandex Managed PostgreSQL для staging/prod (см. TBD_YC_DATABASE_HOST)

2. **Bounded-context schemas** (separate Postgres schemas)
   - [ ] `iam` (users, workspaces, cells, cell_members, consents, refresh_tokens, email_tokens)
   - [ ] `billing` (subscriptions, credit_transactions, invoices, byok_keys)
   - [ ] `agents` (roles, role_versions, team_presets, agent_instances)
   - [ ] `runtime` (tasks, task_steps, tool_calls)
   - [ ] `artifacts` (artifacts, artifact_versions, asset_refs)
   - [ ] `collaboration` (yjs_docs, doc_snapshots)
   - [ ] `memory` (cell_memory_entries, role_memory_entries, embeddings)
   - [ ] `mcp` (mcp_connections, mcp_credentials_refs)
   - [ ] `audit` (append-only audit_log)

3. **Cell-aware schemas per tenant** (ADR-009)
   - [ ] Per-cell schemas (динамически создаются при cell provisioning): `cell_<uuid>.runtime`, `cell_<uuid>.artifacts`, `cell_<uuid>.memory`
   - [ ] Initial migration creates infrastructure для cell-spawning (template-schema + create_cell_schema function)

4. **RLS policies** для всех multi-tenant таблиц
   - [ ] App-user → SET LOCAL `app.current_cell_id` per транзакция (FastAPI dependency)
   - [ ] CREATE POLICY на `USING (cell_id = current_setting('app.current_cell_id')::uuid)`
   - [ ] FORCE ROW LEVEL SECURITY (исключения через superuser only)
   - [ ] Для cross-cell таблиц (e.g. `iam.users`, `iam.workspaces`) — RLS по `owner_id` или membership

5. **SQLAlchemy 2.x + Alembic setup**
   - [ ] `backend/src/shared/db.py`: async engine, async session, RLS context middleware
   - [ ] FastAPI dependency `db_session(user, cell_id)` устанавливает `app.current_cell_id` per request
   - [ ] Alembic `env.py` поддерживает несколько schemas
   - [ ] Initial migration: создаёт все schemas + RLS policies + audit log + cell-template

6. **Models per bounded context**
   - [ ] Базовый Mixin: `id (UUID)`, `created_at`, `updated_at`, `cell_id` (для multi-tenant) или `workspace_id` (для cross-cell)
   - [ ] Pydantic-схемы для API в `<context>/schemas.py`
   - [ ] SQLAlchemy-модели в `<context>/models.py`

7. **Vector storage (pgvector)**
   - [ ] `cell_<uuid>.memory_entries`: id, content TEXT, embedding vector(1024), metadata JSONB
   - [ ] HNSW index на embedding (pgvector 0.7+)
   - [ ] RLS не нужен (per-cell schema уже изолирует)

8. **Audit log**
   - [ ] `audit.audit_log` — partitioned per месяц, append-only (trigger блокирует UPDATE/DELETE)
   - [ ] Поля: id, ts, actor_type (user|agent|system), actor_id, action, resource_type, resource_id, cell_id, workspace_id, payload JSONB, ip, user_agent
   - [ ] Retention 3 года (cleanup job — Wave 3)

9. **Cell provisioning workflow** (см. ADR-009)
   - [ ] `provision_cell(workspace_id, plan_tier, stack_preference) → Cell` функция
   - [ ] Создаёт Cell entity + per-cell schemas + Lockbox path stub
   - [ ] Trial-cell vs paid-cell различия

10. **Тесты**
    - [ ] Integration с testcontainers Postgres
    - [ ] RLS test: user в cell A не видит данные cell B
    - [ ] Audit log: UPDATE на запись audit_log → IntegrityError
    - [ ] Cell provisioning: создание cell → миграции применены к новым schemas
    - [ ] Coverage ≥85%

## Acceptance Criteria

- [ ] `alembic upgrade head` создаёт все schemas + RLS + audit + cell-template
- [ ] `provision_cell()` создаёт working cell с per-cell schemas за <30 сек
- [ ] User в cell W1 запрашивает данные cell W2 → 404 (RLS) или 403 (membership check)
- [ ] Пытаемся UPDATE audit_log → ошибка trigger'а
- [ ] pgvector index работает: `<-> ` запрос возвращает соседей
- [ ] Все таблицы имеют RLS policy ИЛИ явно помечены `BYPASS_RLS_INTENTIONAL` в комменте

## Risks

- **R-05** (cross-cell leak): RLS — основная защита. Тест на bypass обязателен.
- **R-08** (ФЗ-152): ПДн только в РФ — Yandex Cloud Postgres managed-instance в zone ru-central1-*

## Notes for AI-agents

- RLS context устанавливается через FastAPI dependency — НЕ через global state
- Любая новая таблица с `cell_id` ТРЕБУЕТ RLS policy в той же миграции
- Indexes на FK обязательны (Postgres не создаёт автоматически)
- Для cell-spawning: используем PostgreSQL `CREATE SCHEMA cell_<uuid>` + apply template-migrations через Alembic programmatically
