# Phase 00.2 — Custom JWT auth (FastAPI + bcrypt + Redis)

- **Owner:** Tech Lead · **Duration:** 2 дня · **Status:** Pending

## Goal

Working auth-flow: пользователь регистрируется (email/password), получает email-verification, входит, получает JWT + refresh. Backend проверяет JWT на защищённых endpoints. Workspace + initial Cell создаются при первой регистрации.

## Dependencies

- 00.1 (repo) — Done
- OQ-04 (РКН-уведомление) — подано ДО старта (юр.требование)

## Tasks

1. **Auth module** (`backend/src/iam/`)
   - [ ] `models.py`: User, RefreshToken, Consent, EmailVerificationToken, PasswordResetToken
   - [ ] `jwt.py`: pyjwt issue/validate/refresh
   - [ ] `passwords.py`: bcrypt hash/verify (cost factor 12+)
   - [ ] `routes.py`: /api/auth/* endpoints
   - [ ] `middleware.py`: FastAPI dependency `get_current_user()`
   - [ ] `email.py`: SMTP через Yandex 360 (smtp.yandex.ru:587 TLS)

2. **Endpoints**
   - [ ] `POST /api/auth/register` — email + password + consent_pdn → user + verification-email
   - [ ] `POST /api/auth/verify` — email-token → email_verified=true
   - [ ] `POST /api/auth/login` — email + password → JWT + refresh_token (rotation)
   - [ ] `POST /api/auth/refresh` — refresh → new JWT
   - [ ] `POST /api/auth/logout` — blacklist JWT (Redis TTL)
   - [ ] `GET /api/auth/me` — current user info
   - [ ] `POST /api/auth/forgot-password` → reset email
   - [ ] `POST /api/auth/reset-password` — token + new password

3. **JWT structure**
   - Access TTL: 15 минут
   - Refresh TTL: 7 дней
   - Refresh rotation: при каждом refresh → новый refresh + revoke предыдущий

4. **User + Workspace + Cell models**
   - [ ] `User`: id, email, password_hash, email_verified, created_at, last_login_at
   - [ ] `Workspace`: id, owner_id, name, plan_tier, created_at
   - [ ] `Cell`: id, workspace_id, region (default 'ru-central-1'), status, llm_config, stack_preference, secrets_ref (см. ADR-009)
   - [ ] `WorkspaceMember`: workspace_id, user_id, role (owner/admin/member/viewer)
   - [ ] При первой регистрации: создать User + default Workspace + initial Cell (trial)

5. **Consents (ФЗ-152)**
   - [ ] Checkbox в форме регистрации: «Согласен с обработкой ПДн»
   - [ ] Сохранение в `iam.consents` с timestamp + IP + user_agent
   - [ ] Consent type: `pdn_processing` обязателен; `marketing`, `cross_border_transfer` опциональны

6. **Rate-limiting + security**
   - [ ] Redis-based rate-limit: 5 login attempts / 15min per IP+email
   - [ ] HIBP-check при register (опц., через hibp.io API)
   - [ ] Email verification mandatory before first task

7. **Audit log**
   - [ ] Все auth-события → `audit.audit_log` (Wave 0.3 создаёт таблицу)
   - [ ] Поля: action, actor_id, ip, user_agent, ts

8. **Тесты**
   - [ ] Integration: register → verify → login → me → refresh → logout
   - [ ] Negative: invalid creds, expired JWT, blacklisted token
   - [ ] Coverage ≥85% для `iam/` (security-critical)

## Acceptance Criteria

- [ ] `POST /api/auth/register {email, password, consent_pdn:true}` → 201 + user + workspace + initial cell создаются
- [ ] `POST /api/auth/login` → JWT в response
- [ ] `GET /api/auth/me` с JWT → user profile
- [ ] Без JWT — 401 на защищённых endpoints
- [ ] Отозванный JWT — 401 (Redis blacklist работает)
- [ ] Consent сохраняется в БД, доступен в audit
- [ ] Email verification mandatory: без verify нельзя ставить задачи

## Risks

- **R-05** (data leak): JWT TTL = 15 мин, refresh = 7 дней, rotation обязательна
- **R-08** (ФЗ-152): РКН-уведомление ДО приёма первой регистрации; consent checkbox — обязательное поле
- **R-21** (self-hosted auth security): bcrypt cost 12+, pen-test перед public-launch (Wave 2)
