## Goal

Working auth-flow: пользователь регистрируется (email/password), получает email-verification, входит, получает JWT + refresh. Backend проверяет JWT на защищённых endpoints. Workspace + initial Cell создаются при первой регистрации.

**Acceptance metric:** registration → first task ≤ 2 мин (excluding email verification wait), JWT validation overhead < 5ms p95.

### JWT signing key rotation policy

- Access tokens: HS256 with `JWT_SECRET_ACCESS_V<N>` env (rotated quarterly post-launch; Wave 0 hardcoded TBD via Lockbox)
- Refresh tokens: opaque random 256-bit, hashed (SHA-256) before storage
- Key rotation flow (Wave 1+): emit `tech.oriion.iam.key_rotation.v1`, dual-validate с old+new keys для 7-day grace, then revoke old

from src.iam.services.auth_service import LoginCommand, login

### Integration test — refresh-rotation flow

```python
# backend/tests/iam/test_auth_endpoint.py
import pytest
from httpx import AsyncClient

@pytest.mark.integration
@pytest.mark.asyncio
async def test_refresh_token_rotation_revokes_prior_tokens(
    client: AsyncClient,
    db_session: AsyncSession,
):
    """Integration: refresh issues new pair + revokes prior; reuse triggers chain-revoke.

    Per OWASP refresh-rotation: presenting a previously-rotated token MUST
    revoke ALL outstanding tokens for the user + audit alert.
    """
    # Arrange: register + login → original_refresh
    await client.post("/api/auth/register", json={
        "email": "rotate@oriion.dev", "password": "Test123!", "consent_pdn": True
    })
    login_resp = await client.post("/api/auth/login", json={
        "email": "rotate@oriion.dev", "password": "Test123!"
    })
    original_refresh = login_resp.json()["refresh_token"]

    # Act: legitimate refresh
    refresh1_resp = await client.post("/api/auth/refresh", json={"refresh_token": original_refresh})
    new_refresh_1 = refresh1_resp.json()["refresh_token"]

    # Assert legitimate refresh succeeded + original revoked
    assert refresh1_resp.status_code == 200
    assert new_refresh_1 != original_refresh

    # Act: attempt reuse of original (now-revoked) refresh — MUST chain-revoke new_refresh_1
    reuse_resp = await client.post("/api/auth/refresh", json={"refresh_token": original_refresh})
    assert reuse_resp.status_code == 401

    # Verify chain-revoke — new_refresh_1 ALSO revoked after reuse detection
    use_new_resp = await client.post("/api/auth/refresh", json={"refresh_token": new_refresh_1})
    assert use_new_resp.status_code == 401   # chain-revoked
```

## Acceptance Criteria (testable checks)

- [ ] **AC1.** `POST /api/auth/register {email, password, consent_pdn:true}` → 201 + `{user_id, workspace_id, cell_id}` per `api.yaml`. Verified via `test_register_creates_user_workspace_cell`.
- [ ] **AC2.** `POST /api/auth/login` valid credentials → 200 + `{access_token, refresh_token, expires_in: 900}` per `api.yaml`.
- [ ] **AC3.** `GET /api/auth/me` с valid JWT → 200 + user profile per `api.yaml`. Без JWT → 401.
- [ ] **AC4.** Revoked JWT (Redis blacklist hit) → 401. Verified via `test_logout_blacklists_token`.
- [ ] **AC5.** Refresh-rotation chain-revoke: presenting old refresh after rotation → 401 + all user tokens revoked. Verified via integration test `test_refresh_token_rotation_revokes_prior_tokens`.
- [ ] **AC6.** Consent `pdn` recorded в `iam.consents` with timestamp + ip + user_agent + consent_version. Required для регистрации (ConsentMissingError если false).
- [ ] **AC7.** Email verification mandatory — unverified user → 403 на `POST /api/tasks` (verified via integration test).
- [ ] **AC8.** Rate-limit: 6th login attempt в 15min same ip+email → 429. Verified via `test_rate_limit_blocks_6th_attempt`.
- [ ] **AC9.** Coverage ≥85% для `backend/src/iam/` (CI enforced via `--cov-fail-under=85` для iam package specifically).
- [ ] **AC10.** Audit log: каждый auth-event (register/login/logout/refresh) emits row в `audit.audit_log` с structured payload. Verified via `test_login_emits_audit_event`.

## Risks

- **R-05** (data leak): JWT TTL = 15 мин, refresh = 7 дней, rotation обязательна, blacklist на logout (AC4)
- **R-08** (ФЗ-152): РКН-уведомление ДО приёма первой регистрации; consent checkbox обязателен (AC6)
- **R-21** (self-hosted auth security): bcrypt cost 12+, pen-test перед public-launch Wave 2; refresh rotation chain-revoke pattern per OWASP (AC5)
