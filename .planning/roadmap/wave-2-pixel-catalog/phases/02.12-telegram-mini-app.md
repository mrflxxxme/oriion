# Phase 02.12 — Telegram Mini App: мобильный approval-фронт + задачи (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md). Возвращена в W2 решением founder (grill-доп 2026-07-11, **D-25**, суперсид D-03 — место освободилось после удаления WB). Скоуп сознательно **БЕЗ Business API**: 01.11 остаётся parked на RW-05; DM-сценарии (approve DM-replies) добавятся апгрейдом при разблокировке юристом.

- **Status:** ⏳ Pending · **Queue:** предпоследняя фаза волны (после 02.11); первая КАНДИДАТУРА на выживание при затягивании — MCP (02.13) переносится раньше неё (D-27)

**Goal:** пользователь открывает Mini App внутри Telegram и с телефона подтверждает/редактирует исходящие черновики агентов (approval-очередь 02.3), смотрит задачи/артефакты и получает нотификации — без открытия веб-приложения.

**Scope (in):** TMA-контейнер (поддерево `/tma` или второй entry per frontend-аудит; `viewport-fit=cover`, safe-area, `themeParams`-синк на семантические токены DS v0.3); **auth через initData-обмен** (новый backend-эндпоинт: валидация подписи initData → выдача сессии; ветка в auth-store — текущий email+refresh флоу для TMA не годится); поверхности: approval-очередь (список pending → детальный просмотр полного текста → approve/edit/reject — reuse API 02.3), задачи со статусами (SSE/поллинг), артефакты read-only, NPS-виджет (02.0); бот-нотификация «новый pending approval» с deep-link в TMA; конфигурируемый `API_BASE` (из 02.1-retro); **security review Mini App как отдельный evidence-гейт** (новый attack surface: initData-подделка, deep-link инъекции — R-05 из README волны).

**Out-of-scope:** Business API / DM-сценарии (01.11, RW-05 — апгрейд-шов закладывается, функционал нет); Telegram Stars (W3+, ADR-030); создание задач из TMA (read+approve поверхность; создание — по фидбеку беты); pixel-скин в TMA (professional only).

**ADR-refs:** ADR-030 (revised 2026-07-11: Mini App = 02.12 без Business API), ADR-042 (DS v0.3), ADR-014.

**Gating/Runway:** RW-03 (bot-token — уже нужен с 02.3, к этой фазе ожидаемо 🟢); зависит от 02.3 (approval API) + 02.2 (DS v0.3). Tripwire-прогноз: `auth_rbac_sessions` (initData-эндпоинт — новый auth-путь!) + `public_api_contracts` → ack-needed.

**Evidence-гейты:** **adversarial security review обязателен** (initData-валидация: подпись/срок/replay; сессия TMA не эскалируется в полный аккаунт-takeover; deep-links санитизированы); e2e @live: пост из очереди одобрен через TMA → реально отправлен; axe/контраст в теме Telegram. Live-golden бюджет: **~$0.5** (черновики для e2e).

**AC-направления:** TMA открывается из бота и авторизуется по initData без email-логина; полный approve-цикл с телефона работает e2e (draft → TMA approve → отправлено); подделанный/просроченный initData отвергается (тест); нотификация приходит при новом pending и ведёт deep-link'ом на конкретный approval; gate-порог `mini_app_live` (D-28) выполним; ≥N друзей 02.0-когорты воспользовались TMA-approve (замер, не порог).
