# Phase 02.5 — Onboarding-расширение: routing + live-demo + waitlist (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md). НЕ «полный wizard с нуля» (3-шаговый wizard + preset-routing на 3 пресета живёт с 01.12) — точечное расширение под public beta.

- **Status:** ⏳ Pending · **Queue:** после 02.4

**Goal:** новый пользователь из публичного трафика без инструкций выбирает между горизонтальной командой и вертикалями, видит живое демо ценности и доходит до первого артефакта с TTFV ≤3 мин (замер, не гейт — D-17).

**Scope (in):** horizontal-vs-vertical routing UI в wizard (объяснение отличий, рекомендация по описанной пользователем деятельности); live-demo при онбординге (демонстрация примера результата пресета ДО первой задачи — формат решается на discuss: предзаписанный артефакт-пример vs реальный прогон); waitlist-карточки «Скоро» (ИП-Бухгалтерия, СМБ-Sales) с email-signup — вход для выбора W3-вертикали; TTFV-оптимизация по данным 02.0 (baseline из 01.12). Дизайн — на DS v0.3.

**Out-of-scope:** пиксель-тур в wizard (вливается с 02.7, когда спрайты существуют — D-23); новые пресеты (вертикалей в W2 не прибавляется — D-07); маркетинговые страницы (02.8).

**ADR-refs:** ADR-016, ADR-022, ADR-042.

**Gating/Runway:** founder-зависимостей нет. Tripwire-прогноз: frontend + возможно маленький waitlist-эндпоинт (`public_api_contracts` additive) → вероятен exit 0 / лёгкий ack.

**Evidence-гейты:** e2e @live полного пути register→routing→demo→first-task→artifact; axe AA; unit/integration на waitlist. Live-golden бюджет: **~$1** (e2e с реальной задачей).

**AC-направления:** routing доводит до корректного пресета из описания деятельности (сценарные тесты); demo показывается до первой задачи и не блокирует пропуск; waitlist персистит email + сегмент; TTFV-медиана по 02.0-когорте измерена и опубликована в gate-замерах; регрессии onboarding-тестов 01.12 отсутствуют.
