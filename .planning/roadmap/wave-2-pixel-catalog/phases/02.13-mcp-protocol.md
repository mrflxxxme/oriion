# Phase 02.13 — Реальный MCP-протокол + community-серверы + каталог интеграций (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md). Возвращена в W2 решением founder (grill-доп 2026-07-11, **D-26**, суперсид D-04). Замыкающая фаза волны и **первый кандидат на перенос в W3 при затягивании** (D-27, протокол RUNWAY №3 по аналогии). Наши коннекторы (telegram/yandex-disk/imap-smtp) ОСТАЮТСЯ native per ADR-041 — MCP добавляется как второй путь для ЧУЖИХ серверов.

- **Status:** ⏳ Pending · **Queue:** последняя фаза волны (после 02.12)

**Goal:** пользователь подключает внешнюю интеграцию из каталога (W2-набор: **github-mcp + google-sheets-mcp**, D-26), агент вызывает её инструменты через настоящий MCP-протокол под теми же security-швами, что native-тулзы; Wave-0 `MCPClient`-stub заменён рабочим клиентом.

**Scope (in):** MCP-клиент на официальном SDK (`mcp.ClientSession`; транспорты stdio + streamable-http; handshake, `tools/list`, `tools/call`) вместо Wave-0 stub'а; мост MCP-tool → pydantic-ai `Agent(tools=[...])` closure с оборачиванием КАЖДОГО вызова в существующие швы: capability-классификатор (**unknown tool = fail-closed → requires_approval**), DLP-скрин исходящих аргументов, rate-limit, audit-строка; lifecycle серверных процессов/подключений (супервизия, таймауты, degrade-gracefully при падении сервера); creds через `mcp.connector_credentials` (01.9b KMS creds-store; OAuth-токены пользователь приносит свои — per-workspace); материализация `contracts/mcp/schema.sql` + реестр `mcp_connections` в живом использовании; **каталог интеграций в UI** (страница «Интеграции»: native-коннекторы + MCP-серверы единым списком, подключение/creds/отключение); onboarding двух серверов: github-mcp (read-mostly) + google-sheets-mcp (read+draft; запись — только через approval-flow 02.3).

**Out-of-scope:** остальной community-набор (notion/slack/gmail/gdrive → W3 по спросу беты); свои MCP-серверы (native-тулзы не мигрируются — ADR-041); произвольные user-supplied серверы («добавь свой MCP по URL» — W3+, отдельное security-решение); autonomous write в внешние системы (всё DANGEROUS — через 02.3 approve).

**ADR-refs:** ADR-013 (revised: реализация = эта фаза), ADR-041 (amendment: MCP-протокол = 02.13), ADR-014, ADR-039.

**Gating/Runway:** founder-зависимостей нет (OAuth-креды тестовых аккаунтов github/google — agent-owned тест-аккаунты или founder по запросу, решается на discuss). Tripwire-прогноз: `db_migrations` (mcp schema) + `public_api_contracts` + `secrets_keys_crypto` (OAuth-токены) → ack-needed.

**Evidence-гейты:** **adversarial-аудит обязателен** (SECURE-линза: malicious/компрометированный MCP-сервер — tool-descriptions injection, эксфильтрация через аргументы, unknown-tool fail-closed держит); integration: mock-MCP-сервер в тест-харнессе (handshake/list/call/degrade); live round-trip оба сервера (real API). Live-golden бюджет: **~$0.5–1** (агентные вызовы инструментов живой моделью).

**AC-направления:** github-mcp и google-sheets-mcp подключаются из каталога и работают end-to-end (агент читает repo-issue / таблицу в задаче); unknown/новый tool любого сервера ДО классификации = deny (fail-closed тест); упавший MCP-сервер деградирует в понятную ошибку задачи, не крэш; DLP-скрин ловит ПДн в исходящих аргументах MCP-вызова (тест); каталог показывает native+MCP единообразно; gate-порог `mcp_live` (D-28) выполним; Wave-0 stub удалён.
