# Phase 02.0 — Friend-validation: инструментирование + прогон (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md) / [ADR-040 D5](../../../decisions/ADR-040-execution-spec-contract.md). Первая пользовательская фаза; **неблокирующая** — dev-часть маленькая, прогон идёт параллельно всей волне.

- **Status:** ⏳ Pending · **Queue:** сразу после 02.1-retro (dev-часть); рекрутинг — двумя волнами (см. ниже)

**Goal:** 10–15 ICP-друзей прошли путь register→onboarding→задачи на 3 пресетах; собраны воронка-телеметрия (TTFV, task-completion, возвраты), NPS-замеры и качественный фидбек — как вход для приоритизации хвоста волны и выбора следующей вертикали (гейт W2→3).

**Scope (in):** событийная воронка из существующих данных БД (registration → onboarding_completed → first_task_succeeded → artifact_viewed → return-visit), TTFV-вычисление (baseline из 01.12); лёгкий in-app фидбек-виджет (NPS 0–10 + свободный текст) с триггером после N выполненных задач (**D-13**, интервью 2026-07-11); admin-срез для founder (SQL-view/простая страница). Прогон: **волна 1** — 2–3 близких друга сразу после retro (их фидбек по навигации — вход research-этапа 02.2); **волна 2** — остальные 10–15 после мержа 02.2 (tier-1 первое впечатление).

**Out-of-scope:** сторонняя продуктовая аналитика (PostHog и т.п. — решение на гейте W2→3); NPS как порог (это замер, не гейт — ADR-040 D5); маркетинговый трафик (02.8).

**ADR-refs:** ADR-040 (D5), ADR-016.

**Gating/Runway:** рекрутинг друзей = founder-работа (обе волны). **ДВА БЛОКЕРА (grill 2026-07-15) — без них фаза паркуется (ADR-040 D7):**
1. **`user_production` капы (D-32, founder-решение).** `per_request` / `per_organization_per_month` / `kill_switch` в [cost-budget v5](../../../../.claude/agents/_shared/cost-budget.yaml) всё ещё `null`; политика требовала задать их «перед wave-1-to-2 гейтом» — гейт подписан PASS с null'ами. Это первая фаза с реальным клиентским LLM-трафиком: **`null` молча означает «без потолка»** при оценке самого файла $5000–15000/мес. Статус `caps_unset_BLOCKS_02.0` снимается простановкой чисел.
2. **PII-скрин на LLM-границе (D-35) приземлён в 02.1-retro.** Dev-зависимость. Без него [D-36](../../../_session-context/DECISIONS-LOG.md) (закрытая бета без артефакта согласия) теряет обоснование — трансграничная передача в КНР случится на первом же таске первого друга, и вернётся вопрос мини-согласия на ПДн.

Tripwire-прогноз: чистый frontend + 1 маленький API-эндпоинт фидбека → вероятен exit 0; `public_api_contracts` при новом эндпоинте (additive) → ack-needed.

**Правовой режим (D-36):** 02.0 — **закрытая дружеская бета** по личным приглашениям, не публичное предложение. Артефакт согласия не требуется — обоснование целиком опирается на блокер 2 (нет трансграничной передачи → нет ст. 12). Полный юрпакет (Политика/ТоС/текст согласия/РКН-уведомление/юрист OQ-03) гейтит **02.8** (публичные лендинги), не эту фазу. NB: локализация БД в РФ (ст. 18.5) и трансграничная передача (ст. 12) — разные обязанности; хранение в РФ вторую не закрывает.

**Evidence-гейты:** unit+integration на воронку-запросы и фидбек-эндпоинт; axe на виджет. Live-golden фазы: **N/A ($0)** — собственные гейты LLM не вызывают. ⚠️ Не путать: **сам прогон фазы генерирует `user_production`-расход** (10–15 друзей × реальные задачи) — это другой cost_source, и он не покрыт ни dev_team, ни live_golden конвертами. Отсюда блокер 1.

**AC-направления:** воронка вычислима одним запросом/страницей по каждому другу; NPS-ответы персистятся с cell-контекстом (RLS); TTFV-медиана вычислима по когорте; виджет не показывается повторно после ответа; данные волны 1 доставлены в 02.2-research.
