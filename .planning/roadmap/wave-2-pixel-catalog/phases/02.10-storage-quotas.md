# Phase 02.10 — Storage-quota enforcement (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md). Deferred из 01.5 (RQ-20260701-002, grill 2026-07-03: HARD-REJECT семантика; триггер «реальные тарифы live» наступает с 01.3b). Субстрат учёта `cell_storage_usage` готов с 01.5.

- **Status:** ⏳ Pending · **Queue:** после 02.9 (логически после 01.3b — реальные тарифы)

**Goal:** upload в ячейку с исчерпанным тарифным лимитом (Trial 1ГБ / Solo 5ГБ / Команда 10–200ГБ) получает **HARD-REJECT** с понятной ошибкой; на 90% заполнения пользователь получает алерт.

**Scope (in):** admission-check на S3 upload-url выдачу + inline/Yjs-записи по `cell_storage_usage` vs лимит плана (`billing.plans` + активная подписка); HARD-REJECT ответ с кодом/текстом + UI-обработка; 90%-алерт (in-app + email); лимиты в каталоге планов (сид-обновление); учёт освобождения места при delete (проверить/дочинить декремент usage).

**Out-of-scope:** докупка сторэджа как отдельный SKU (W3); per-artifact лимиты; компакция/архивирование.

**ADR-refs:** ADR-012, ADR-038, ADR-008.

**Gating/Runway:** логическая связка с 01.3b (тарифы), но исполнимо и до live-платежей (лимиты по каталогу). Tripwire-прогноз: возможен `db_migrations` (лимиты в plans) → лёгкий ack; остальное вне растяжки.

**Evidence-гейты:** integration real-PG+MinIO: заполнение до лимита → reject; ровно-на-границе кейсы; 90%-алерт; конкурентные uploads у границы (гонка). Live-golden: **N/A ($0)**.

**AC-направления:** превышение невозможно ни одним путём записи (S3/inline/Yjs — тест на каждый); reject не ломает задачу-родителя (graceful); алерт одноразовый на пересечение 90%; usage корректен после delete; лимиты читаются из каталога планов, не хардкод.
