# Phase 01.12 — Dashboard UI + Onboarding wizard (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md) / [ADR-040](../../../decisions/ADR-040-execution-spec-contract.md). Дорастает до полной спеки на discuss-шаге. «Integration last» — интеграционная фаза волны.

- **Status:** Pending · **Queue:** последняя must-фаза Wave 1 (ADR-040 D4)

**Goal:** новый пользователь проходит путь register → onboarding wizard (3 шага) → trial-cell auto-spawn → первая задача через выбранный пресет (horizontal или вертикаль) → результат на Dashboard — без инструкций со стороны.

**Scope (in):** Dashboard UI (задачи/артефакты/баланс кредитов/память — сводная поверхность поверх готовых API); Onboarding wizard 3 шага (ADR-022 hybrid: wizard-структура + LLM-подсказки); trial-cell auto-spawn на register (billing Trial уже начисляется — 01.3); маршрутизация horizontal-vs-vertical пресетов (каталог: productivity-core + agency_marketing_ru + telegram_creator); 3 demo-сценария; visual base = tokens v0.2 (00.8).

**Out-of-scope:** полный onboarding 5 пресетов (Wave 2 02.5); Pixel skin (Wave 2); маркетинговые страницы (02.7); memory-панель (готова в 01.4-ui — только линк).

**ADR-refs:** ADR-001, ADR-022, ADR-016, ADR-031.

**Gating/Runway:** зависит от 01.4-ui и 01.10 (каталог из 2 вертикалей) — потому «integration last». Founder-зависимостей нет. Tripwire-прогноз: в основном frontend (вне растяжки); возможен лёгкий backend (trial-cell auto-spawn touch `iam`/`multitenancy` → `auth_rbac_sessions` ack).

**Evidence-гейты:** e2e @live полного пути register→wizard→task→artifact (Docker + funded) — высокая контрольная ценность → live-golden бюджет ~$1–2; adversarial audit.

**AC-направления:** полный путь проходим e2e без ручных действий; 3 demo-сценария зелёные; wizard корректно маршрутизирует на все 3 пресета; TTFV измерен (baseline для W2-метрики ≤3 мин); axe AA.
