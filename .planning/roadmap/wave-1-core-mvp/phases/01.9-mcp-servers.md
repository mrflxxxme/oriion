# Phase 01.9 — MCP-серверы (наши) + активация security-защит (seed-spec)

> Seed-spec per [DoR](../../DEFINITION-OF-READY.md) / [ADR-040](../../../decisions/ADR-040-execution-spec-contract.md). Дорастает до полной спеки на discuss-шаге.

- **Status:** Pending · **Queue:** после 01.8c

**Goal:** три собственных MCP-сервера (telegram-mcp v0.2 Bot-API scope, yandex-disk-mcp, imap-smtp-mcp) доступны агентам через существующий MCP-клиент (00.4), и **ни один коннектор не открыт без активной DLP** (ADR-040 D10).

**Scope (in):**
1. **Precision-tuning DLP ПЕРВЫМ:** ИНН-детектор FP ≤1% на golden-корпусе PII (гасит DV-04/DV-05) → оба флага (`security_dlp_enabled` + injection-sanitize) **ON** — блокирующий AC, предусловие остального скоупа.
2. telegram-mcp v0.2 — **Bot-API** scope only (Business-API остаётся за feature-flag 01.11, GATED RW-05).
3. yandex-disk-mcp + imap-smtp-mcp; каждый tool-вызов проходит DLP-скрин + capability-классификатор (fail-closed, 01.6 substrate).
4. Tools-allowlist per role обновлён; audit-строка на каждый внешний вызов.

**Out-of-scope:** vertical-коннекторы (Bitrix24/amoCRM/WB/Ozon → Wave 2 02.4); community-MCP; Telegram Business-API (01.11).

**ADR-refs:** ADR-013, ADR-039, ADR-014, ADR-040 (D10).

**Gating/Runway:** dev-часть автономна (моки). Live-проверка telegram-mcp дешевле с RW-03 (bot-token), но не гейтится им — можно evidence-проверить на mock-транспорте, live-smoke добавить при разблокировке. Tripwire-прогноз: `secrets_keys_crypto` (llm_gateway/creds-хранение коннекторов), возможно `db_migrations` (registry коннекторов).

**Evidence-гейты:** adversarial audit (3 линзы, приоритет SECURE: exfiltration через коннектор) + docker-integration. Live-golden: контрольная ценность есть (агент реально дергает tool через MCP) → бюджет ~$1–2.

**AC-направления:** FP ≤1% доказан на корпусе; оба флага ON в дефолт-конфиге; DLP-блок срабатывает на synthetic-ПДн в исходящем tool-вызове каждого коннектора; capability-классификатор режет вызов вне allowlist роли; 3 сервера отвечают в MCP-клиенте.
