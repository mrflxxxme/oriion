## Goal

Новый bounded context `security`: **input/output фильтрация** (prompt-injection на
входе внешнего контента, DLP-сканер РФ-ПДн на выходе deliverable) + **capability
классификатор** (риск инструмента + enforcement-seam) — всё на **детерминированном
слое B** (regex + checksum), с порт-швом под будущий ML (A). Guardrail-швы в
runtime зеркалят `quota_admission` / `memory_extraction` (default `None` ⇒ no-op в
unit; worker подключает реальный, gated флагом Settings).

## Verification

- `make lint typecheck test` (ruff + mypy --strict + bandit + unit). **Docker не нужен** — фаза детерминированная, без DB-таблиц/миграций (DLP-audit идёт через уже-integration-проверенный `emit_audit_event`; в unit — fake `AuditSink`).
- Evidence per ADR-037 D3: `evidence/adversarial_audit.json` (3 линзы) + manifest, `head_sha` = финальный коммит PR. **НЕ требуется:** `docker_integration` (нет нового DB-пути) · `live_golden` (нет LLM) · `judge_panel` (нет широкого форка).
- Adversarial audit: 3 линзы (SOUND / **SECURE** особо / NO-REGRESSIONS), refute-by-default. Ключевые проверки SECURE-линзы: (a) сырое ПДн НЕ утекает в лог/audit-payload/SSE/exception-message; (b) checksum-детекторы без ReDoS; (c) injection B1 не ломает легитимный контент.

## Enforcement activation (cross-ref, НЕ в этой фазе)

- **01.9** — флип `security_dlp_enabled=True` + `security_injection_scan_enabled=True` + реальный capability-gate (`requires_approval` в dispatch outward-tools) + owner-config surface.
  - **ОБЯЗАТЕЛЬНО при активации (precision-tuning на реальных данных, adversarial-аудит 2026-07-03):** ИНН-10 (юрлицо) checksum пропускает **~10%** произвольных 10-значных чисел → легитимный документ с номерами заказов/счетов рискует ложным hard-block'ом. Перед flip'ом: (a) добавить контекстный якорь (токен «ИНН»/«INN» рядом с числом) ИЛИ (b) считать одиночный checksum-valid 10-значник low-confidence (не hard-block), ИЛИ (c) исключить ИНН-10 как не-ПДн (юрлицо публично; личный = ИНН-12). ИНН-12/СНИЛС (2 контрольных разряда, ~1% FP) — ОК. Валидировать на реальных RU-документах.
- **01.12** — approval-UI ложится на тот же `OutputDlpScreen` шов.
- **Wave-2+** — ML detector-порт (A): Prompt Guard / bge, нулевое изменение call-site.

## Adversarial audit (2026-07-03, 3 линзы, refute-by-default)

- **SECURE ✅ PASS** (0 P0/P1): центральный инвариант «сырое ПДн не утекает» устоял под трейсингом всех путей (findings/DlpViolation/audit-payload/SSE/логи); ReDoS опровергнут (linear injection + capped DLP); checksums валидны против реальных ИНН/СНИЛС; audit-персист на failure-пути подтверждён.
- **SOUND → 1 P1 пойман+закрыт:** DLP скринил усечённый `_deliverable_text` (12000-cap, только summary+artifacts) → на горизонтальном пути `screened ⊉ delivered` (ПДн за cap'ом / в др. полях проходило). Фикс: `_dlp_screen_text` = полная сериализация `output.model_dump()` без cap.
- **NO-REGRESSIONS → 1 P2 закрыт:** `injection_scan` default-ON калечил легитимный веб-контент (голые `developer mode`/`jailbreak`, markdown-заголовки `## Instructions`). Фикс: default OFF + trim паттернов.
- **P3 (robustness, закрыт):** DLP-блок ловил только `DlpViolation` → non-DLP ошибка скрина оставляла task 'running'. Фикс: `except Exception` стампит failed.
- **P3 (deferred → 01.9):** ИНН-10 ~10% FP (см. активацию выше). P3 O(n²) regex на pathological input — безвреден (capped + DLP off).
