## AC pin block (verbatim lift)

### From Phase 00.5b audit

- **AC-W1-1** — **SSEPublisher Redis-pubsub bridge** (closes F-ARC-H2). Replace
  the in-process `InProcessSSEPublisher` singleton with a Redis pub/sub-backed
  publisher so SSE streaming survives multi-worker deployment. Wave-0 ships with
  `workers=1` as the invariant guarding this gap. **Acceptance:** stack runs
  `gunicorn -w >1`; a task dispatched on worker A streams its events to a
  `/stream` subscriber pinned to worker B.
- **AC-W1-2** — **Per-step TaskStep persistence + per-callsite metrics.** Persist
  a `task_steps` row per LLM call / delegation with token + cost split (Wave-0
  rolls cost up only at task level). **Acceptance:** each delegation produces a
  `task_steps` row with non-zero `cost_credits`; `task.total_*` == sum of steps.
- **AC-W1-3** — **Master-Agent schema extension.** Add the Master-Agent layer
  above Coordinator for vertical-template orchestration (per ADR-029).
  **Acceptance:** schema migration + provisioning path for a Master-Agent that
  spawns multiple cells.
- **AC-W1-4** — **TaskRepository port + outbox.** Introduce a repository port for
  tasks + a transactional outbox for CloudEvents (Wave-0 emits log-only
  envelopes). **Acceptance:** events written to an outbox table in the same TX as
  the state change; a relay publishes them.
- **AC-W1-5** — **cancel_cascade real-PG testcontainers + SSE-stream proper
  test** (extends F-TR-M1). Replace the unit-mock cancel-cascade + the
  route-registration-only SSE test with a testcontainers-PG integration test that
  drives a real orchestrator dispatch and asserts the streamed event order +
  cascade rows. **Acceptance:** integration test subscribes to `/stream`, runs a
  real dispatch, asserts `task.started → … → task.completed`, then cancels and
  asserts cascade.
- **AC-W1-6** — **GUC tenant-context helper extract.** ✅ **CLOSED Phase 00.6
  PR-A Commit 3** (`588e979` — `auth_service.register` wraps provisioning in
  `async with set_tenant_context(...)`). Retained here for audit-trail; no Wave-1
  work remaining.
- **AC-W1-7** — **NullTeamProvisioningService no-op default.** Provide a Null
  implementation so `AuthService` unit tests don't need the real provisioning
  service and the optional-`None` constructor seam can collapse. **Acceptance:**
  `CoordinatorDeps`/`CoordinatorDepsLike` shim duality removed; one deps type.
- **AC-W1-8** — **DelegateInput.target_agent_slug pattern constraint.** Add a
  Pydantic pattern/enum constraint so an invalid slug fails at validation, not at
  dispatch. **Acceptance:** `DelegateInput(target_agent_slug="bogus")` raises a
  validation error.
- **AC-W1-9** — **Provider key rotation via YC Lockbox.** PARTIAL — Phase 00.6
  PR-B Terraform (`lockbox.tf`) ships Lockbox provisioning + the deploy workflow
  materializes `/opt/oriion/.env` from it. Remaining: backend reads Lockbox
  **directly via SDK at startup** (drop the on-disk `.env` materialization) + a
  rotation procedure with no downtime. **Acceptance:** rotating a Lockbox secret
  version is picked up without redeploy; no secret on VM disk.
- **AC-W1-10** — **GigaChat OAuth refresh-after-expiry test.** Add a test that
  exercises the GigaChat OAuth token refresh path after expiry (double-endpoint
  MockTransport). **Acceptance:** test forces an expired token and asserts a
  refresh round-trip before the chat call succeeds.

### From Phase 00.6 PR-A audit

- **AC-W1-11** — **OTel header-sanitization processor** (closes F-SEC-M2). Add an
  OTel span processor that drops `Authorization` (and other secret-bearing)
  headers from httpx spans so LLM provider keys can't leak into traces.
  **Acceptance:** a span captured for an outbound LLM call contains no
  `Authorization` header value.
- **AC-W1-12** — **OTel SDK thread-safety** (closes F-ARC-M1). Make
  `setup_otel()`'s module-level `_tracer_provider` + `_instrumented` mutation
  atomic so lifespan re-entry in multi-worker mode doesn't race. **Acceptance:**
  concurrent lifespan inits don't double-instrument; flag flips atomically.
- **AC-W1-13** — **Per-callsite metric instrumentation** (closes F-ARC-L1).
  Instrument the orchestrator + LLMRouter + cost_recorder call-sites so the 9
  Prometheus metrics expose real values (Wave-0 registers them but they read 0).
  Also refresh `pricing_service` to DeepSeek **V4** rates (per ADR-018 V4 drift
  amendment) so cost is real, not the Wave-0 coarse estimate in
  `runtime/dispatch.py::estimate_credits`. **Acceptance:** `/metrics` shows
  non-zero `llm_request_total` + `task_duration_seconds` after a demo run; task
  cost derives from `billing_service.record_llm_cost`, not the estimate.
- **AC-W1-14** — **Loki retention 90d + audit_log archival** (closes F-CMP-M2,
  ФЗ-152). Raise Loki retention to 90d and ship chunks to the RU-zone Object
  Storage bucket (`loki_archive`, provisioned in Phase 00.6 PR-B
  `object_storage.tf`); archive the `audit_log` to long-term cold storage for the
  3-year ledger. **Acceptance:** Loki config retention=90d; chunks land in the
  bucket; audit-log archival job documented + tested.
- **AC-W1-15** — **Alertmanager Telegram/PagerDuty receivers** (closes F-CMP-L1).
  Replace the Wave-0 mock receiver with real Telegram + PagerDuty webhooks so
  critical alerts (e.g. R-04 cost runaway) page someone. **Acceptance:** firing a
  test alert delivers to Telegram + PagerDuty.

### From Phase 00.6 PR-B audit (NEW)

- **AC-W1-16** — **orchestrator-dispatch swap to Dramatiq.** Phase 00.6 PR-B
  closed the PR-A CRITICAL FINDING (queued-but-never-dispatched) with an
  **inline-synchronous** endpoint `POST /tasks/{id}/run` + a **ScriptedCoordinator**
  deterministic researcher→analyst→writer pipeline (`runtime/dispatch.py`). Two
  swaps for Wave-1: (a) move dispatch onto a **Dramatiq actor** so the endpoint
  returns 202 immediately instead of blocking the request thread for the whole
  orchestration; (b) replace `ScriptedCoordinator` with the **real LLM-driven
  Coordinator** once `LLMGatewayModel.request()` forwards tools + the
  structured-output schema to the provider (the AC14 tool-call path). **Acceptance:**
  `POST /tasks/{id}/run` returns 202 < 1s; the orchestration runs in a Dramatiq
  worker; the Coordinator decides decomposition via an LLM tool-call, not a fixed
  pipeline; SSE ledger + AC8/AC9/AC10 still hold on the 10× demo.
- **AC-W1-17** — **proper src/agents unit tests.** Phase 00.6 PR-A C20 deferred
  the `src/agents` per-module ≥85% coverage gate (`2e58fad`). Add real unit tests
  for the agents bounded context (archetype/team/role-prompt services, the 4
  agent factories, `delegate_task` guards) and re-enable the strict gate in
  `ci-backend.yml`. **Acceptance:** `src/agents` coverage ≥85% with the per-module
  gate wired (matching tasks/runtime); the AC13-strict deferral comment removed.
- **AC-W1-18** — **Yandex Search XML parser + read_url for the Researcher.**
  Phase 00.6 PR-B wired live `web_search` into the Researcher via a scripted
  pre-fetch using **Brave** (founder decision 2026-06-07). Two follow-ups:
  (a) implement the Yandex Search XML→results parser in `mcp/tools/web_search.py`
  (Wave-0 returns `[]` for the real Yandex path — only JSON test mocks parse),
  so RU-sovereign search becomes usable + ФЗ-152-preferable; (b) wire `read_url`
  (already implemented in `mcp/tools/read_url.py`) so the Researcher can fetch
  top competitor pages for depth (Wave-0 uses snippets only). **Acceptance:**
  Yandex backend returns real results from live XML; Researcher optionally
  deep-reads top-N URLs within the AC10 cost cap.
- **AC-W1-19** — **web_search via the real tool-call path.** Once AC-W1-16 lands
  the LLM-driven Coordinator + `LLMGatewayModel` tool-forwarding, replace the
  scripted `runtime → mcp.tools.web_search` pre-fetch (ADR-024 §3 Exception #3)
  with the Researcher Agent calling `web_search` as a native Pydantic-AI tool
  through the gateway (rate-limited via the Redis `ToolRateLimiter`).
  **Acceptance:** Researcher autonomously decides when/what to search; the
  direct runtime→mcp edge is removed.

### From Phase 00.6 PR-B LIVE validation (2026-06-08)

- **AC-W1-20** — **single-source the role-prompts.** Phase 00.6 PR-B C13 packaged
  `backend/role_prompts/*.md` into the image (the loader walk doesn't reach
  `.planning/contracts/role-prompts/` inside the container). That's now a
  duplicate of the canonical `.planning/contracts/role-prompts/`. **Acceptance:**
  one source of truth — either a build-time sync step, package-data via
  `importlib.resources`, or move the canonical copy into `backend/`.
- **AC-W1-21** — **Russian Trusted Root CA in the backend image + YandexGPT
  catalog.** Live run: GigaChat failed with `SSL CERTIFICATE_VERIFY_FAILED` —
  the RU Trusted Root CA is on the host but NOT in the `python:slim` container
  (would also break GigaChat on staging). Install it in the Dockerfile prod
  stage (like the VM cloud-init does) OR honour `GIGACHAT_VERIFY_SSL=false`.
  Also: `yandexgpt-pro` was an invalid model name (404) — fixed to
  `yandexgpt/rc` = YandexGPT 5.1 Pro (C16/17); document the catalog-enablement
  prerequisite. **Acceptance:** GigaChat TLS verifies in the container; all 3
  providers reachable.
- **AC-W1-22** — **writer output conformance.** Live DeepSeek brief was 1018
  words (target ≥1500) and the model wrapped its own heading around the
  instructed `### Пост N` (`#### ### Пост N` — parser fixed in C19). Tune the
  writer role-prompt + sub-prompt to reliably hit ≥1500 words + the exact
  content-plan heading format. **Acceptance:** AC9 brief-length passes on the
  10× cohort.
- **AC-W1-23** — **per-role `max_tokens` + decouple AC8 latency from output
  length.** C18 raised the global `max_tokens` 2048→8192 (the writer was
  truncated). Two follow-ups: (a) per-role caps (the researcher/analyst don't
  need 8192); (b) the AC8↔AC9 tension — a longer brief (AC9) pushes past the
  120s AC8 cap on the inline single-worker path. The real fix is streaming +
  the Dramatiq actor (ties AC-W1-16) so latency is decoupled from generation
  length. **Acceptance:** brief ≥1500 words AND cohort p95 ≤120s together.
