## Goal

Add the **account layer on top of the existing cost ledger** so Wave-1 friends-clients run
tasks against a real credit budget. The cost engine already exists (01.2): `record_llm_cost`
writes a per-call debit into the append-only `billing.credit_transactions` ledger and
`budget_guard` enforces the per-task 50/100 cap. This phase delivers tariffs, the
trial/subscription grant, balance/usage read APIs, the published credit-rate, BYOK fee-mode
plumbing, and **aggregate caps (per-cell + per-day R-04)** so runaway cost is contained.

Scope was grilled (2026-06-22) to a focused slice matched to current reality (multitenancy is
**single-cell-per-workspace** → multi-seat Команда tiers can't be enforced yet).

## Scope (delivered)

- **Schema** (`billing/0002_plans.py`, `billing/0003_subscriptions.py`): `billing.plans` global
  tariff catalog (no per-tenant RLS, seeded with all 6 ADR-008 tiers) + `billing.subscriptions`
  (cell→plan + period + trial state) with RLS (`sub_cell_isolation` on `current_cell_id()`),
  partial-unique one-active-per-cell, `updated_at` trigger.
- **Models + repositories** (`billing/models.py`, `billing/repositories/`): `Plan`, `Subscription`
  + `PlanRepository`, `SubscriptionRepository` (registered via `models_registry` for the worker tract).
- **Trial provisioning** (`billing/services/subscription_service.py`): idempotent `start_trial`
  (14-day Trial sub + 500-credit `trial_grant`) + `assign_plan` (operator-driven paid activation).
  Wired into `iam.auth_service.register` via a `TrialProvisioning` Null-object port (mirrors
  `agents.TeamProvisioning`), inside register's existing `set_tenant_context` block.
- **Balance/usage** (`billing/services/balance_service.py`): `get_balance` / `get_period_usage`
  / `get_daily_usage` / `list_transactions` — SUM aggregates over the ledger.
- **Aggregate caps** (`billing/services/quota_service.py` + `runtime/orchestrator.py`): per-cell
  soft-warn + hard-block + per-day kill-switch (R-04), enforced at task admission via an injected
  `quota_admission` seam (default None ⇒ no-op for unit tests; the worker wires the real check).
  `CellQuotaExceeded` / `DailyQuotaExceeded` → `task.failed` with the billing code.
- **BYOK plumbing** (`llm_gateway/billing_service.py`): a BYOK-paid call (byok_key_id set) writes
  the usage_log audit row but **skips the credit debit** — no platform credits consumed. Cost
  sum-check refined to managed-usage-only. `plan.byok_allowed` is the catalog gate flag.
- **API** (`billing/routers/billing.py`, `/api/v1/billing/*`): `credit-rate`, `plans`,
  `subscription`, `balance`, `transactions`; `BillingError` → RFC 7807 problem+json handler.
- **Credit-rate** (`billing/services/credit_rate_service.py`): publishes Wave-0-1 operative facts
  (1 credit = 1 RUB, role_multiplier 1×, current FX from `FX_RATE_USD_TO_RUB`).

**Out of scope (named follow-ups):** **ЮKassa test-mode top-up (01.3b)** — payment-create +
webhook→credit grant; live-flip gated OQ-02/OQ-19. **Rollover/expiry** (50% / ≤1mo / 60-day) +
its periodic job. **Команда multi-cell enforcement** (needs multi-cell provisioning).
**Overage-fee billing** (+% per tier) — Wave 1 hard-blocks instead. **BYOK plan-flag live
enforcement** (no live BYOK call/create path in Wave 1 — all BYOK HTTP endpoints are 501 stubs).
**Live ЦБ FX feed** (Wave 2).

## Worker-path live golden — ✅ DONE (2026-06-23, funded DeepSeek)

Ran the real async worker tract (isolated pg+redis + local backend:8001 + Dramatiq worker on the
funded `.env`) via `scripts/live_golden_worker_billing.py` + `scripts/live_cap_check.py`:

- **Dispatch** `POST /run` → 202 in **~0.02s** (AC-W1-16a).
- **Trial (01.3):** register → `GET /billing/balance` = **500**; subscription = trial.
- **Debit (01.3, RLS-billing persistence):** worker orchestrated the brief (3 delegations) →
  task `succeeded`, `total_cost_credits` ≈ **5.06** (≤50), balance **500 → ~495**, **3 debit rows**
  persisted, period-usage reconciles.
- **Redis-SSE (AC-W1-1):** `GET /stream` replayed the worker's ledger **cross-process** — 8 frames
  (`task.started` → 3× delegation_started/completed → `task.completed`) read back from the redis Stream.
- **Per-day cap (01.3 / R-04):** seeded usage ≥ 150 → task **blocked at worker admission** →
  `DailyQuotaExceeded` → `task.failed` `error_code=billing.daily_quota_exceeded`, ~0 cost (also pinned
  by the real-PG `test_per_day_kill_switch` + the orchestrator seam test).

**Worker-infra fix (pre-existing 01.2, NOT 01.3):** the worker runs `asyncio.run()` per message (fresh
loop each) and recreated the DB engine per message, but the **redis SSE client was a process-global
singleton bound to the first loop** → the 2nd dispatched message crashed `RuntimeError: Event loop is
closed`. **Fixed:** the worker now builds + closes the redis SSE publisher + redis client *per message*
(`build_sse_publisher` / `build_redis_client` / `RedisSSEPublisher.aclose`) like the engine, and selects
the Selector event-loop policy on Windows — which enabled the full **Redis-SSE** run above (unit-pinned
by `test_worker_sse_lifecycle`). **Residual:** the **local-Windows** worker still *intermittently* stalls
on a 2nd dispatched task's redis publish (Windows-asyncio-redis flakiness — not deterministic, not a
billing/code defect), so each live golden runs against a fresh worker; the definitive multi-task
worker-path run belongs in CI/Linux (Redis-SSE already proven there, PR #64/#65).
See [[teamly-worker-asyncio-loop-redis-finding]].
