### Verdict: **APPROVE WITH FOLLOW-UPS**

The PR-B fix is architecturally sound for Wave-0. The inline-synchronous dispatch is the correct minimal call given the deferred LLMGatewayModel tool-call path, the workers=1 invariant is **enforced** (not merely documented), AC-W1-16 is a correct and sufficient Wave-1 pin, and the Terraform decomposition is clean with the state-bucket chicken-and-egg handled and DNS conditional sound. The one item that must land in THIS PR is a small ADR-024 §3 amendment to record the new importing file `runtime/dispatch.py` under Exception #2 — the *edge* (runtime→tasks.models.Task) is already sanctioned, but the amendment is file-scoped and a new file now carries it.

---

### Strengths

1. **workers=1 invariant is enforced, not just documented.** `infra/docker-compose.staging.yml:40-47` ships `gunicorn ... -w 1` with an inline comment tying it to F-ARC-H2. This is the load-bearing fact that makes inline-dispatch + in-process SSEPublisher correct: `/run` (publish) and a concurrent or subsequent `/stream` (subscribe via drain-replay) share one process-wide singleton. The phase-spec skeleton's stale `-w 4` was corrected. Honest hardening pin (AC-W1-1 / AC-W1-16) for the Redis-pubsub swap.
2. **ScriptedCoordinator returns `CoordinatorOutput` + a `_ScriptedRunResult` shim with `.output`** (`dispatch.py:243-257`) so `execute_agent_task` serializes the deterministic path **identically** to the future LLM path (`orchestrator.py:165-216` reads `.output`/`.data` then `model_dump()`). The swap surface for AC-W1-16 is a single constructor injection — no orchestrator change required. Clean seam.
3. **Honest AC evidence boundary.** The docstring (`dispatch.py:14-28`) is explicit that only the *decomposition* is deterministic; each specialist is a real `LLMGatewayModel` call through the `LLMRouter` failover chain, so AC8 (latency), AC9 (artifact shape), and AC10 (cost) remain real end-to-end measurements. The stand-in does not fake the metrics — it fakes only the planning decision, which is the AC14-deferred capability.
4. **Failure path is closed.** `orchestrator.py:156-192` wraps `Agent.run()` so any exception emits `task.failed` SSE + refunds reserved budget — subscribers exit via the sentinel (`sse_publisher.py:52-57`) instead of hanging. This is exactly the class of bug PR-A had (stream-waits-forever); the fix generalizes it.
5. **Terraform decomposition is textbook.** Seven concern-scoped files (network / compute / managed_pg / managed_redis / lockbox / dns / object_storage) + main/backend/variables/outputs/versions. State backend chicken-and-egg explicitly documented (`backend.tf:1-17`, `object_storage.tf:7-9`) with bootstrap-by-hand + `-backend=false` offline-validate path. DNS is `count`-gated on `var.manage_dns` (default false) — sound for a domain registered off-YC. ФЗ-152 enforced via a `regex` validation on `yc_zone` (`variables.tf:27-31`) and `assign_public_ip=false` on managed PG.

### ADR-024 §3 amendment question — explicit answer

**YES — ADR-024 §3 needs an amendment, and it must land in THIS PR.**

- The *edge* runtime→`tasks.models.Task` is **already sanctioned** (Exception #2).
- BUT Exception #2 is written file-scoped and lists only `runtime/orchestrator.py`. PR-B introduces a **new importing file**, `backend/src/runtime/dispatch.py:56`, that imports `Task` and writes child `Task` rows. ADR-024's own governance rule (lines 192-200) requires every new cross-context model import to be recorded with `file:line`. The Status line (line 3) explicitly asserting "no new sanctioned imports" is now stale.
- The fix is a one-paragraph edit (add the two `dispatch.py` lines to Exception #2, bump the Status date), reusing the existing Wave-1 candidate (TaskRepository port, already pinned by AC-W1-16). It does not require new architectural justification — only a record update.
- All other PR-B edges are fine without amendment: `dispatch.py`→`agents.*` and `dispatch.py`→`llm_gateway.*` are **service/factory imports** (sanctioned-by-default table, ADR-024:182-187); `tasks.routers.tasks.py`→`runtime.dispatch` and `→runtime.sse_publisher` are function imports (same direction stream.py already uses, not model imports).
