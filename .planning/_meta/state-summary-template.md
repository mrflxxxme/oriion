# Состояние проекта — шаблон справки (state-summary)

> Нормативный формат «справки о состоянии проекта» per founder-директиве 2026-07-09.
> Раннер (`/autonomy:run`) эмитит её **на каждой фазе** (continuous, exit-ritual §6e — дельта фазы)
> и **на закрытии волны** (wave state-summary — полная картина). Две обязательные секции:
> **техническое состояние** + **реализованные пользовательские сценарии**.

---

## Phase state-summary (дельта одной фазы — в JOURNAL-запись + PR-body + prepend в `PROJECT-STATE.md`)

### Фаза NN.M — <название> (<дата>, PR #NN)
**1. Техническое состояние (дельта):** какие модули/файлы добавлены/изменены; новые таблицы/миграции/флаги; какие гейты (lint/type/test/security/coverage/evidence) прошли; deploy-статус (смержено / на VPS / verified); ключевые архитектурные решения (ADR/DECISIONS-LOG refs).

**2. Реализованные пользовательские сценарии (дельта):** что теперь может конечный пользователь end-to-end, чего не мог до фазы. Формулировать как сценарий: «Пользователь <роль> может <действие> → <результат>». Если фаза чисто инфраструктурная — «нет прямого user-facing изменения; включает <возможность> для будущих фаз».

**3. Что отложено / нужно от founder (если есть):** DV-записи, founder-гейты (review/creds/sign-off), follow-up chips.

---

## Wave state-summary (полная картина волны — `roadmap/<wave>/WAVE-N-SUMMARY.md`)

### 1. Техническое состояние волны
- **Архитектура:** bounded-контексты, ключевые ADR волны, стек-дельта.
- **Что построено:** по модулям/фазам — сжато.
- **Качество:** агрегат гейтов (unit/integration/security/coverage), evidence-артефакты, adversarial-аудиты, live-goldens.
- **Deploy:** что на проде/staging, версия, verified-факты (что именно проверено на сервере).
- **Долг/риски:** открытые DV (класс), deferred-security, known-gaps.

### 2. Реализованные пользовательские сценарии
Полный список сквозных сценариев, которые пользователь может пройти после волны (не по фазам, а по ценности). Каждый: «Пользователь может <сценарий> → <как проверено: e2e/live-golden/server-verify>».

### 3. Что нужно от founder для формального закрытия волны
Founder-гейты (sign-off, review draft→reviewed, cost/risk review), креды-разблокировки (RUNWAY), решения по parked-фазам.

### 4. Метрики/бюджет
Спенд волны (dev-team, приблизительно), число фаз/PR, heal-события, founder-touchpoints.
