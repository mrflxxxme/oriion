# ADR-040 — Spec-contract автономного исполнения: DoR, реестры, гейты, бюджет

- **Status:** Accepted
- **Date:** 2026-07-07
- **Context link:** founder-интервью 2026-07-07 (12 решений, session `docs-refinement-interview`), [ADR-037](./ADR-037-autonomous-multiphase-runner.md)
- **Ревизует:** ADR-037 (расширяет D4/D6), ADR-024 (§охраняемый контракт), cost-budget.yaml v2→v3
- **Расширяет:** ADR-025 (acceptance-gate format), ADR-026 (validation pipeline)

## Контекст

ADR-037 передал merge-authority гейт-стеку, и контур провёл фазы 01.5–01.8 в бою. Аудит документации (2026-07-07, три параллельных исследования: методология / roadmap / код-vs-доки) показал 10 разрывов, из-за которых следующие автономные прогоны либо примут неверные решения, либо остановятся там, где могли бы продолжать: неспецифицированные фазы без формальных критериев готовности, устаревшие wave-гейты (до-2026-05-15 скоуп), растяжка D2 на дрейфующих рукописных контрактах, скрытый долг «мягких» AC, разбросанные founder-зависимости, двойное имя TEAMLY_RU/Oriion.

Founder-интервью (12 вопросов, каждый с анализом и рекомендацией) зафиксировало решения ниже. Все D-пункты нормативны для `/autonomy:run`.

## Решения

### D1 — JIT + Definition-of-Ready (DoR)

Спеки фаз генерируются JIT (как раньше), но фаза допускается к `execute` только после валидации против [`roadmap/DEFINITION-OF-READY.md`](../roadmap/DEFINITION-OF-READY.md). DoR-провал = эскалация, не «раннер сам решил, что хватит». Каждая фаза **текущей** волны получает seed-spec (5–15 строк констрейнтов: цель, границы, ключевые ADR, gating, ожидаемый live-golden бюджет) уже при регенерации PHASES.md — полная спека дорастает из seed на discuss-шаге. Волны N+2+ остаются направлениями без спек.

### D2 — Охраняемый публичный контракт = OpenAPI-snapshot

Машинная растяжка `public_api_contracts` переезжает с рукописных `.planning/contracts/**` на **генерируемый снапшот** `.planning/contracts/openapi.snapshot.json` (экспорт живой FastAPI-схемы; CI-job сверяет снапшот с кодом, breaking-diff = tripwire-категория). Рукописные `contracts/<ctx>/api.yaml` понижаются до **design-time черновиков** (без охранного статуса; расхождение с живым API не является нарушением). `contracts/<ctx>/schema.sql` сохраняют нормативность (проверяются миграциями). Реализация снапшота+CI — фаза 01.8c; до её мержа растяжка работает по-старому (fail-safe: глоб `.planning/contracts/**` уже покрывает и будущий снапшот).

### D3 — Рабочее имя: Oriion

«Oriion» — единое рабочее имя во всём репо (README, Makefile, API title, docstrings, промпты). OQ-09 (финальный бренд/домен) остаётся открытым; финальное имя, если изменится, заменяется одной механической операцией. Кодовая часть ренейма (main.py, тесты, role-prompts c SemVer-бампом) — в 01.8c; доки — немедленно.

### D4 — Очередь Wave-1 и must-множество закрытия

Очередь: **01.8c → 01.9 → 01.4-ui → 01.10 → 01.12**. Must для закрытия Wave 1: **01.9 + 01.4-ui + 01.10 + 01.12** (01.10 держит вторую вертикаль — без неё «Core MVP» теряет смысл; нужен только bot-token, живёт в RUNWAY). Гейтед-фазы **01.3b / 01.8b / 01.11** НЕ блокируют закрытие волны: паркуются в [`FOUNDER-RUNWAY.md`](../FOUNDER-RUNWAY.md) и вливаются в очередь по мере разблокировки, либо переносятся в Wave 2 решением гейта.

### D5 — Гейт Wave-1→2: только технические пороги

Блокирующие пороги: `acceptance_criteria_pass_rate ≥ 0.9` + все must-фазы (D4) смержены + DEFERRED-VERIFICATION без просроченных записей класса P1. Людская валидация (друзья/внешние пользователи) переносится в **Wave 2 фазу 02.0** (первая пользовательская фаза, неблокирующая для остального трека Wave 2). NPS измеряется в 02.0, но не является блокирующим порогом (выборка 10–15 друзей статистически шумна). Правило: **любая реорганизация roadmap обязана в том же PR обновить затронутые gate-файлы** (проверяется exit-ритуалом).

### D6 — Реестр отложенной верификации + обязательная retro-фаза

Единый реестр [`DEFERRED-VERIFICATION.md`](../DEFERRED-VERIFICATION.md): каждый «мягкий» AC (stub-level, plumbing-only, flags-OFF, deferred live-проверка) обязан иметь запись (ID, фаза-источник, что не доказано, чем доказывается, фаза-погашение). **Мягкий AC без записи в реестре = блокирующий review-flag.** Паттерн `NN.1-retro` формализуется: первая фаза каждой волны — retro, погашающая записи реестра, адресованные этой волне.

### D7 — FOUNDER-RUNWAY + preflight

Все founder-зависимости (креды, юр-решения, OQ) — в одном манифесте [`FOUNDER-RUNWAY.md`](../FOUNDER-RUNWAY.md). Раннер на preflight сверяет очередь с манифестом: фаза с неудовлетворённой зависимостью **паркуется до старта** (RUN-QUEUE `parked` + notify), очередь продолжается со следующей независимой фазы.

### D8 — Роли → нативные сабагенты

11 persistent-ролей конвертируются из хендбуков в нативные спавнабельные сабагенты (`.claude/agents/<role>.md`); judge-panel (ADR-037 D5) и reviewer-линзы исполняются реальными независимыми спавнами с изолированным контекстом. Закрывает признанный gap ADR-037 («роли — хендбуки, не сабагенты»). Реализация — фаза 01.8c, до 01.9.

### D9 — Синхронизация пользовательской документации

Exit-ритуал дополняется обязательными пунктами: (а) README «текущая фаза» актуальна; (б) runbook затронутых фич обновлён/создан; (в) фазный файл смерженной фазы не в статусе Pending. Плюс лёгкая CI-проверка свежести (реализация в 01.8c): смерженная фаза со статусом Pending в своём spec-файле = red.

### D10 — DLP: точность → включение, блокирующий AC фазы 01.9

Порядок в 01.9: precision-tuning ИНН-детектора (цель **FP ≤ 1%** на golden-корпусе) → оба флага (`security_dlp_enabled`, injection-sanitize) **ON** → только затем открывается первый MCP-коннектор. Формулируется как блокирующий AC фазы 01.9: **коннекторы не выходят без активной DLP**.

### D11 — Бюджетная политика v3

`dev_team.per_day`: **soft $20 / hard $40** (было 30/75). Live-goldens — **только там, где дают контрольную ценность** (фаза трогает LLM-путь/промпты/оркестрацию; детерминированные фазы — N/A, как 01.6/01.7). Ожидаемый live-golden бюджет — строка DoR каждой фазы. При достижении soft-cap раннер **доводит текущую фазу до конца и паркует очередь** (не бросает фазу посередине), notify founder. cost-budget.yaml → v3.

### D12 — Гигиена канона (принято без развилки)

Статусы Wave-0 фазных файлов синхронизируются с фактом (ретроактивная пометка as-built); wave-0-to-1 gate: проза приводится к amended-фронтматтеру; JOURNAL >150KB — архивация в `dev-log/archive/` (maintenance-chip).

## Последствия

- `/autonomy:run` получает три новых обязательных шага: RUNWAY-preflight, DoR-валидация на discuss, doc-sync в exit-ритуале.
- «Зелёная» фаза больше не может молча оставить недоказанный AC — реестр делает долг видимым и погашаемым machine-driven retro.
- Гейт Wave-1→2 становится автономно вычислимым; людской сигнал сознательно сдвинут в Wave 2 (02.0) как измерение, а не порог.
- Растяжка D2 после 01.8c охраняет фактический публичный контракт, а не устаревший документ.
- Бюджетный конверт ужат вдвое: multi-phase прогоны дешевеют, длинные цепочки паркуются раньше — осознанный trade-off против R-31.

## Alternatives considered

- **Полные спеки на волну вперёд** — отклонено: Wave-0 опыт показал дрейф предзаписанных спек; DoR даёт проверяемость без тонн устаревающего текста.
- **NPS ≥30 как блокирующий порог гейта** — отклонено: выборка 10–15 друзей даёт ±30 пунктов шума; сигнал сохраняется как измерение в 02.0.
- **Ручная актуализация contracts/ как источника истины** — отклонено: дисциплина уже провалилась (frontend официально доверяет живому API); генерация дешевле и точнее.
- **Включение DLP как есть (~10% FP)** — отклонено: ложные блокировки легитимных задач на первых реальных каналах хуже недельной задержки включения.
