# ADR-037: Autonomous multi-phase runner + gate-authority merge

- **Status:** Accepted
- **Date:** 2026-07-01
- **Deciders:** Founder (grill session `/grill-me`, 2026-07-01)

## Context

Текущий воркфлоу (ADR-023 runtime + ADR-027 git/PR + ADR-015 hygiene) на практике исполняется **вручную, одной Claude-сессией на фазу**: founder делает preflight, отвечает на ~7-форковый грил, говорит «приступай», агент имплементит + запускает audit-сабагентов, гоняется local CI, exit ritual, PR — и **founder читает диф и мёржит каждый tier 3+ PR** (по ADR-027 §5 это фактически каждая фаза). Роскошный pipeline из ADR-023 (11 persistent ролей, CloudEvents-DAG, revision-loops) — в основном «спроектировано, не исполняется» (ADR-023 §6: живёт «L1 — gsd-субагенты через Agent tool»).

Три силы давят на смену:

1. **Скорость.** Сессия-на-фазу = налог на ре-bootstrap контекста каждый раз; фазы идут строго по одной.
2. **Время founder'а.** Founder в петле ≥4 раза за фазу (preflight, грил-форки, «приступай», ревью+мёрж).
3. **Автономность решений.** Founder хочет, чтобы агенты сами находили *оптимальные* решения на пути к цели, а не собирали его мнение по каждому форку.

Constraint, который нельзя нарушить: **«не потерять стабильность».** Founder согласен выйти из merge-петли **только при условии**, что security/integrity/local-run гейты станут *строже*, а не слабее. Доверие переносится с глаз founder'а на машину, и машина обязана его отработать верифицируемо.

Guiding principle (из грила): **автоматизировать полностью, но держать узкие, чётко определённые «растяжки» на том, что может навредить, и делать целостность машины верифицируемой.**

## Decision

Переходим на **автономный многофазный runner, где строгий гейт-стек — merge-authority, а не глаза founder'а**; founder в петле только на исключениях (узкие растяжки + продукт-эскалации + застрявшие гейты). Восемь нормативных решений:

### D1 — Review posture: полная автономия мёржа на всех тирах

Founder выходит из merge-петли на **всех** тирах. Это **ревизует ADR-027 §5** («Founder = всегда финальный approver для tier 3+»). Условие активации: D2–D3 (усиленные гейты) построены и зелены **до** включения раннера.

### D2 — Задняя растяжка: узкий список категорий → 1-клик ack

Авто-мёрж всё зелёное, **КРОМЕ** изменений, задевающих:

- миграции БД по существующим таблицам / RLS-политики,
- auth / RBAC / сессии,
- billing / денежные пути,
- секреты / ключи / шифрование,
- слом публичных API-контрактов (`.planning/contracts/`).

Эти фазы готовятся, доводятся до зелёного и **ПАУЗЯТ на founder 1-клик ack** перед мёржем. Детект — по path-глобам диффа (`.claude/autonomy/tripwire.yaml`). Ожидаемо ~95% фаз мёржатся автономно.

### D3 — Целостность гейтов: evidence-артефакт + CI-verify

Гейты, которые GitHub CI прогнать **не может** (live-голдены с funded LLM, Docker-интеграция с реальными сервисами, 3-lens adversarial audit), обязаны эмитить **коммит-привязанный evidence-артефакт**: `{gate, head_sha, timestamp, verdict, cost_usd, details}`. Новый CI-job (`ci-evidence`) ассертит: для заявленных фазой гейтов артефакт существует, свежий (`head_sha == github.sha`), `verdict == PASS`. Агент **физически не может** смёржить зелёное без доказательства, привязанного к коммиту. Побочно: артефакты = post-hoc audit trail для founder-аудитора.

### D4 — Передняя растяжка: эскалация только на product/market + необратимом

Агент **владеет всеми implementation + архитектурными форками** (пишет ADR через template + логирует решение в JOURNAL/decisions-log). Эскалирует к founder **только**: (1) продуктово-рыночное поведение, требующее знания ЦА/рынка (что видит юзер, цена, scope-cut), (2) трипвайр-категории из D2. Передняя растяжка — зеркало задней.

### D5 — Оптимальность: judge-панель только на широких форках

Большинство задач — один проход (быстро/дёшево). На **широких форках** (выбор архитектуры / алгоритма / схемы) — N независимых подходов → роль `evaluator` (ADR-023) ранжирует по рубрике **корректность → безопасность/целостность → простота/поддерживаемость → стоимость → перформанс** → победитель + прививка лучших идей проигравших. Дорогая генерация только там, где окупается. planner/architect флагует широкие форки в PLAN.md.

### D6 — Runner: секвенциальная цепь в одной сессии + opt-in worktree-параллелизм

Founder поднимает Docker + funded `.env`, запускает `/autonomy:run`. Раннер крутит цикл по очереди фаз:
`discuss(auto) → plan → execute (+ judge-панель на широких форках) → гейты (CI + evidence) → tripwire? ack : auto-merge → следующая фаза`,
пока не упрётся в: эскалацию (D4) / ack (D2) / красный гейт, который fix-loop не чинит (D7) / пустую очередь. Независимые треки могут идти **параллельно в отдельных git-worktree** (opt-in, только при явной независимости — иначе секвенциально из-за меж-фазных зависимостей). Убирает налог ре-bootstrap.

### D7 — Rollback: авто-реверт регрессии + автономный fix-loop + уведомление

Если авто-смёрженная фаза позже роняет гейт на `main` (CI следующей фазы / ночной ре-прогон голденов), раннер **автоматически ревертит** тот мёрж (`main` зелёный по построению — реверт сам обратим), спавнит **автономный fix-цикл** (перепланировать → пофиксить → прогнать гейты → ре-мёрж) и **уведомляет founder о реверте**. Разработка продолжается; цикл фиксов максимально автономен; но о реверте founder узнаёт в момент, когда он случился.

### D8 — Notify: desktop push + RUN-QUEUE + Telegram-мост

Раннер обязан достучаться до founder на **5 interrupt-событиях**: нужен ack трипвайра / product-эскалация / случился реверт / красный гейт застрял / прогон завершён. Каналы: нативный `PushNotification` (десктоп) + `.planning/_session-context/RUN-QUEUE.md` (pending acks / эскалации / реверты + диагноз) + **Telegram-мост** (сохранённый `chat_id`) для phone-side апрува ack/эскалаций, когда founder не у машины.

### Порядок сборки (предохранители ДО автономии)

Согласие founder'а на D1 обусловлено существованием D2–D3, поэтому строим рельсы первыми:

- **Блок A — Рельсы:** evidence-схема + `ci-evidence.yml` + tripwire-конфиг + PreToolUse/pre-merge хук + branch protection.
- **Блок B — Фронт:** auto-discuss/эскалация-политика + decisions-log + judge-панель.
- **Блок C — Runner:** `/autonomy:run` + auto-merge-on-green + RUN-QUEUE + notify + Telegram-мост.
- **Блок D — Self-healing:** auto-revert + fix-loop + post-merge regression-watch.
- **Блок E — Параллелизм:** opt-in worktree для независимых треков.

## Consequences

- ✅ **Скорость:** цикл фазы теряет 4 founder-точки и налог ре-bootstrap; фазы сцепляются в одной сессии.
- ✅ **Верифицируемая целостность:** D3 делает local-only гейты неподделываемыми; `main` зелёный по построению (D7). Стабильность растёт, а не падает — прямое исполнение constraint'а founder'а.
- ✅ **Audit trail для post-hoc аудитора:** evidence-артефакты + decisions-log + RUN-QUEUE дают founder'у полную картину «что случилось, пока меня не было».
- ⚠️ **Trade-off — стоимость:** автономный многофазный прогон + judge-панель жгут токены; раннер обязан уважать `.claude/agents/_shared/cost-budget.yaml` (per-day soft/hard, per-month kill-switch) и принимать per-run budget-cap на старте (R-31).
- ⚠️ **Trade-off — риск авто-реверта:** авто-реверт может ошибиться; смягчается тем, что реверт сам обратим + founder уведомляется немедленно (D7/D8).
- ⚠️ **Разрыв реализации:** 11 ролей в `.claude/agents/<role>/` — хендбуки, а не нативные spawn-абельные сабагенты; раннеру нужен role-prompt-лоадер или конверт в нативные сабагенты (задача Блока B/C).
- 🔮 **Future:** после Блока E независимые треки идут параллельно; cron-режим (безнадзорный ночной прогон) остаётся отклонённым, пока Docker/funded-.env под founder-контролем (см. Alternatives).

## Alternatives Considered

| Альтернатива | Pro | Contra | Почему отклонили |
|---|---|---|---|
| **Полное ревью, только фронт быстрее** (D1-alt) | Доверие к гейтам не меняется | Founder остаётся в петле на каждой фазе | Не бьёт в главный налог — время founder'а на хвосте |
| **Ноль растяжки — всё авто** (D2-alt) | Макс. скорость | Необратимое (данные/деньги/секреты) без предохранителя | Против «не потерять стабильность» |
| **CI — твёрдый гейт, локальные — self-report** (D3-alt) | Проще | live/integration держатся на честном слове агента | Дыра целостности под автономией — неприемлемо |
| **Всегда multi-approach + judge** (D5-alt) | Макс. качество | 2–3× токены/время на фазу | Конфликт с «быстрее» + cost-budget |
| **Фоновый/scheduled cron-runner** (D6-alt) | Макс. hands-off | Docker + funded-.env под founder-контролем ломают безнадзорные live/integration гейты | Против «не потерять стабильность»; отложено до снятия Docker-констрейнта |
| **Fix-forward без реверта** (D7-alt) | Сохраняет темп | Сломанный `main` живёт до фикса | `main`-green-by-construction важнее темпа |
